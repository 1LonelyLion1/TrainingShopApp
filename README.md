# Рога и копыта

Flutter-приложение: каталог товаров с фильтрами, корзиной и оформлением заказа.
Каталог и корзина работают без сети. Данные берутся из
[Fake Store API](https://fakestoreapi.com/docs).

## Запуск

Нужен Flutter 3.47.

```bash
flutter pub get
flutter run
flutter analyze
flutter test

# после изменения таблиц drift или DI-аннотаций
dart run build_runner build --delete-conflicting-outputs
# после изменения строк в lib/l10n/*.arb
flutter gen-l10n
```

Целевые платформы: Android и iOS.

## Выбор стека

| Задача | Выбор | Почему |
| --- | --- | --- |
| Состояние | `flutter_bloc` (Cubit) | Явные состояния Loading / Success / Error / Empty, простое тестирование без UI и без кодогенерации. |
| Сеть | `dio` | Раздельные таймауты и типизированные ошибки, что напрямую нужно для требования о разных сообщениях. |
| Кеш | `drift` (SQLite) | Типизированная схема, атомарная замена данных в транзакциях и готовый механизм миграций. Хранилище скрыто за интерфейсами, поэтому логика от него не зависит. |
| Локализация | `flutter_localizations`, `intl`, `gen-l10n` | Официальный подход Flutter: строки в ARB, типобезопасный доступ, плюрализация ICU. Новый язык добавляется отдельным ARB-файлом. |
| DI | `get_it`, `injectable` | Граф зависимостей описан аннотациями и проверяется при генерации. Окружения позволяют подменить базу в тестах. |
| Навигация | `go_router` | Декларативные маршруты, вкладки с сохранением состояния через `StatefulShellRoute` и простая замена стека после оформления заказа. |
| Сеть онлайн/офлайн | `connectivity_plus` | События смены сети для автоматического обновления каталога. |
| Изображения | `cached_network_image` | Дисковый кеш, чтобы загруженные картинки были видны офлайн. |

## Архитектура

```text
lib/
  app/        приложение и маршруты
  core/       DI, база данных, ошибки, сеть, форматирование денег, общие виджеты
  l10n/       строки интерфейса (ARB) и сгенерированный код
  features/
    catalog/  data, domain, presentation
    cart/     data, domain, presentation
    checkout/ domain, presentation
    settings/ data, presentation
```

- Зависимости направлены так: UI → Cubit → Repository → API и кеш.
- `get_it` используется только при старте и для создания `CheckoutCubit`. Экраны получают остальные Cubit через `BlocProvider`, поэтому виджет-тесты обходятся без контейнера.
- Цены хранятся в целых центах, поэтому итог корзины не накапливает ошибку `double`.
- Каталог открывается сразу из кеша и обновляется в фоне.
- Записи корзины выполняются строго по очереди, чтобы старая запись не перетёрла новую.
- Ошибки сводятся к типам: нет сети, таймаут, 5xx, 4xx, пустой ответ, неверный формат.
- Домен не содержит текста интерфейса: ошибки и валидаторы возвращают типы, а сообщения выбирает UI.
- Корзина хранит снимок товара в своей таблице и не зависит от обновлений каталога.

## Решения, в которых сомневался

- **Пустой ответ.** Пустое тело считается ошибкой, а корректный `[]` показывается как состояние Empty. `[]` не перезаписывает кеш, чтобы сбой API не стёр товары, доступные офлайн. Минус: если каталог действительно опустеет, офлайн будут видны старые товары.
- **Цена в корзине.** В корзине хранится снимок товара, поэтому позиция доступна, даже если товар исчез из каталога. Цена при обновлении каталога не меняется. В реальном магазине цену должен подтверждать сервер при оформлении.
- **Телефон.** Проверяется только формат и количество цифр (10–15). Для реального продукта лучше подошла бы библиотека на основе libphonenumber.

## Что не успел и как бы доделал

- **Проверка реального интернета.** `connectivity_plus` видит подключение к сети, но не доступ в интернет. При Wi-Fi без интернета каталог не обновится сам, пока не сменится сеть или пользователь не повторит запрос. Добавил бы периодический повтор с экспоненциальной задержкой и обновление при возврате приложения из фона.
- **Картинки офлайн.** Кешируются только уже показанные изображения. Можно предзагружать их после обновления каталога.
- **Заказ.** Он создаётся локально и никуда не отправляется, а данные формы не сохраняются. Для продакшена нужны API, идемпотентность и история заказов.
- **Хранилище.** При росте каталога добавил бы индексы и пагинацию на уровне запросов, а также тесты миграций схемы. Для Web понадобилась бы отдельная настройка drift (WASM).
- **Тесты.** Покрыты логика и экран каталога. Добавил бы golden-тесты и интеграционный сценарий от каталога до заказа.
- **Релиз.** Нужны release-подпись Android, настройка команды iOS, собственные иконки и единый идентификатор приложения на обеих платформах.
- **Локализация.** Интерфейс доступен на русском и английском, язык меняется в настройках и сохраняется между запусками. Названия и описания товаров приходят из API на английском и не переводятся. Название приложения под иконкой задано в нативных файлах и пока только на русском.
- **Измененме количества товара в корзине.** Сейчас увеличение/уменьшение количества товара работает сразу по нажатию. Стоит добавить задержку что бы не нагружать api и базу лишими нажатиями при быстром изменение количества товара в корзине. Так же стоит  добавить ввод конкретного количества товаров.
- **Пагинация.** В реальном проекте могут быть тысячи товаров и для оптимизации загрузки стоило бы добавить пагинацию. Но для этого должна быть поддержка фильтров и пагинации на стороне api.
- **Синхронизация корзины.** Корзину желательно синхронизировать с api но в рамках задачи мы не используем api для корзины. В реальных проектах стоит предусмотреть мердж корзины либо по сессии либо по пользователю.
- **Подтянуть flutter.** Стоит подтянуть flutter до актуального так как много что после .47 деприкейтнуто.
- **Адаптивная верстка** Так как появилось много раскладных устройств нужно реализовать адаптивнуб верстку. В частности обязательно для ios до 7 апреля(сроки мог напутать) так как после обновлять приложения без этой поддержки будет невозможно(правила магазина изза iphone duo). 
- **UiKit** На большом проекте стоит сформировать UiKit пакет для удобства
